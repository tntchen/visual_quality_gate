# 前端体验走查与提测准入辅助工具

本仓库用于零贷部门前端体验走查工具的需求澄清、技术验证和后续开发。当前暂定方案是“浏览器采集扩展＋部门内分析端＋按需只读版本关联＋报告驱动的部门软门禁”。

> **当前阶段：立项准备与需求澄清。** 仓库尚无应用代码，需求基线、试点技术形态、终端条件和部署条件均未完全确认，不应直接按完整系统开工。

## 先读什么

1. [项目交接文档](docs/00_Work系统开发项目交接文档.md)：当前最重要的系统边界和最小闭环建议。
2. [AI 项目上下文](docs/ai/project-context.md)：资料扫描后的当前事实、问卷新输入和未决分歧。
3. [需求方确认事项清单](docs/03_需求方确认事项清单.md)：组织澄清会和跟踪决策。
4. [调查问卷工作簿](docs/前端体验走查工具调查问卷.xlsx)：已包含一份 2026-11-13 的回收回答；它是单方输入，不是最终需求结论。
5. [立项执行计划](docs/01_立项准备总体思路与执行计划.md)与[前期调查建议](docs/04_前期调查方向与参与人员建议.md)：用于计划和调查。
6. [需求细项拆解](docs/02_需求细项拆解.md)：仅作候选需求池，不作为已确认开发范围或验收基线。

AI 助手从根目录 [AGENTS.md](AGENTS.md) 开始；人类开发者同时阅读 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 当前不能跳过的问题

- 回收问卷将目标排为“A 部门自测 → C 公司系统硬阻断 → B 统一分析平台”，且对软门禁仍需讨论；这与一期软门禁建议尚未形成一致意见。
- 问卷建议选择手机银行，并关注 iOS、安卓、鸿蒙三端一致性；真实页面技术形态及浏览器扩展是否适用尚未确认。
- “设计、开发、测试”被填为核心流程，尚需改问并确认一条真实业务操作流程。
- 首批范围出现三端一致性、视觉还原和加载体验，需要先澄清优先级、判定依据和一期承载能力。
- 目标浏览器或客户端、扩展分发、部门分析机器、数据保存位置、接口权限和长期责任人仍待确认。

完整来源与冲突说明见[资料登记册](docs/ai/source-register.md)，近期工作见[项目路线图](docs/ai/roadmap.md)。

## 目录约定

```text
.
├── AGENTS.md                 # Kimi、Codex、WorkBuddy 的共同入口和工作约束
├── CONTRIBUTING.md           # 两位开发者的 Git 与评审流程
├── README.md                 # 人类项目入口
└── docs/
    ├── 00～04_*.md           # 原始交接、计划和需求资料
    ├── 调查问卷/             # 分角色空白问卷与回收模板
    ├── *.xlsx                # 问卷原始工作簿，包含已回收回答
    └── ai/                   # 工具中立的 AI 协作文档
        ├── project-context.md
        ├── source-register.md
        ├── engineering-guardrails.md
        ├── collaboration.md
        ├── roadmap.md
        ├── decisions/        # ADR：重要技术与协作决策
        ├── tasks/            # 独立任务说明，避免共享看板冲突
        └── handoffs/         # 跨开发、跨 AI 会话交接
```

后续代码目录应根据评审后的技术选型建立，不在需求未清时预设语言或框架。业务证据、真实截图、接口报文、账号凭据和运行数据不得提交到本仓库。

## 协作最小规则

- 使用 `main` 作为集成分支，两位开发各自使用短生命周期分支，通过合并请求交叉评审。
- 开始工作前先检查未提交修改；不要覆盖另一位开发或 AI 会话留下的变更。
- 每个任务明确范围、非目标、验收和验证结果；未运行的测试不得写成已通过。
- 需求、架构或接口发生重要变化时，同步更新原始依据、AI 项目上下文和必要的 ADR。
- 不同 AI 工具产生冲突建议时，由人类开发者依据项目资料决策；不采用“最后一个 AI 说了算”。

详细流程见[AI 协作规范](docs/ai/collaboration.md)。
