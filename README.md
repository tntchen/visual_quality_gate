# 前端体验走查与提测准入辅助工具

本仓库用于零贷部门前端体验走查工具的需求澄清、技术验证和后续开发。当前一期主需求是“在提测前通过代码扫描比对 UE 设计与 UI 规范，输出可定位、可解释、可人工复核的不符合项”。App／浏览器插件保留为后续真实终端补充验证的可选方案，不再作为一期主闭环的必要前提。

> **当前阶段：立项准备、需求澄清与技术预研。** 已形成一期初始需求草案，但具体场景、代码与 UE 映射、首批规则、权限和验收条件尚未冻结，不应直接按完整系统开工。

## 远程仓库

代码托管在 GitHub：<https://github.com/tntchen/visual_quality_gate>（当前为私有仓库，仅受邀协作者可见）。

```bash
git clone https://github.com/tntchen/visual_quality_gate.git   # 首次获取
git switch main && git pull --ff-only                          # 开始工作前同步主分支
```

日常开发在自己的任务分支上进行，完成后通过 Pull Request 提交另一位开发评审合并，不直接推 `main`。任务认领、分支命名（`<type>/<short-scope>`）、提交格式（`type(scope): 简要说明`）和评审检查项统一按 [CONTRIBUTING.md](CONTRIBUTING.md) 执行，任务占用优先使用 GitHub Issue。

## 1.0.0 开发分支

- **当前工作分支**：`dev/1.0.0`，于 2026-11-15 基于 `main` 的 `ec28878` 提交创建。
- **分支用途**：承载 1.0.0 的需求澄清、技术预研和后续开发工作；具体任务仍使用独立短分支并遵循交叉评审流程。
- **状态边界**：该分支是版本工作分支，不是稳定标签或发布分支；创建分支不代表需求已经冻结、正式技术选型已经完成或 1.0.0 已经发布。
- **当前预研重点**：代码—UE—UI 规范的可比较性、代码组件映射、首批确定性规则、差异报告及代码与设计资产的安全边界。

## 当前不能跳过的问题

- UE 设计与 UI 规范的可用形态、版本及结构化程度尚未确认，不能直接承诺代码与设计图片的自动比较。
- 试点代码范围及代码组件与 UE 页面／组件的对应关系尚未建立。
- 首批规则、正例、反例、允许差异和争议样本尚未评审。
- 静态代码检查不能替代真实渲染、动态数据和全部机型兼容验证，补充验证边界需明确。
- 报告最终核验人、设计争议裁决人、长期维护责任和三项主成功指标仍待确认。
- 代码只读权限、部门内分析机器、UE 资产与报告的保存和访问条件仍待确认。

完整来源与冲突说明见[资料登记册](docs/ai/source-register.md)，近期工作见[项目路线图](docs/ai/roadmap.md)。

## 协作最小规则

- 使用 `main` 作为集成分支，两位开发各自使用短生命周期分支，通过 GitHub Pull Request 交叉评审，任务认领与分配优先使用 GitHub Issue。
- 开始工作前先检查未提交修改；不要覆盖另一位开发或 AI 会话留下的变更。
- 每个任务明确范围、非目标、验收和验证结果；未运行的测试不得写成已通过。
- 需求、架构或接口发生重要变化时，同步更新原始依据、AI 项目上下文和必要的 ADR。
- 不同 AI 工具产生冲突建议时，由人类开发者依据项目资料决策；不采用“最后一个 AI 说了算”。

详细流程见[AI 协作规范](docs/ai/collaboration.md)。
