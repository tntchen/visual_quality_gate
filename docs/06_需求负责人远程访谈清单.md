# 需求负责人远程访谈清单（20 分钟以内）

- **建议日期**：2026-11-16
- **访谈对象**：需求负责人
- **访谈目标**：确认一期路径、试点流程、首批范围、门禁责任、App 采集前置条件的确认责任和三项成功标准
- **主持建议**：1 人主持、1 人记录并计时；会前发送本清单和第 3、6 题选项

## 1. 会前准备

1. 手机银行中最适合试点的一条真实用户业务流程；
2. 第 13 题八项已选成功标准中最重要的三项。

主持人准备记录表，字段包括：结论、未决原因、决策人、责任人、完成日期、影响文档。

## 3. 主持人口播与追问

### 开场（0:00～1:00）

> 今天只确认一期需求方向和后续责任，不展开技术方案。线上表单有几项模板内容没有采集，我们会补最关键的责任与边界，其余会后书面确认。希望 20 分钟内形成明确结论；不能当场回答的，只登记责任人和日期。

### 1. 目标与门禁路径（1:00～4:00）

**主问：**

> 您在第 3 题填写了 `acb`，我们理解为“A 部门体验自测和报告准入 → C 公司系统硬阻断 → B 统一分析平台”。请确认：A 是否就是一期主目标，C 和 B 是否属于后续阶段？

**必须继续确认：**

> 您是否接受一期先以有效报告进行人工提测准入，不自动阻断公司研发协同系统？

- 若接受：记录为一期路径，C/B 后续再评估。
- 若不接受且 C 必须一期实现：记录“暂停部门工具全面实施，先评估公司系统能力和立项路径”。
- 若仍无法决定：明确最终决策人和最晚决策日期，不进入全面开发。

**不要展开：** 公司接口字段、门禁技术实现和统一平台功能清单。

### 2. 试点应用与真实流程（4:00～8:00）

**主问：**

> 手机银行试点请先只选一条真实用户业务流程。它的入口是什么，用户完成哪几个关键步骤，出现什么结果算成功？

**必要追问：**

> 这条流程主要使用原生页面、H5，还是混合形态？您提到的三端不一致是否就发生在这条流程中？

**采集前置条件追问（约 1 分钟，不展开技术方案）：**

> 这条试点流程能否提供专用测试包，并安排一名客户端对接人？如果您不确定，请明确由谁在什么时间前确认。

> 试点是否允许在测试包中开启必要的页面检查能力？目前是否知道存在禁止截屏、禁止调试、敏感信息不得保存等限制？不确定的部分请指定客户端或终端安全负责人会后确认。

- 需求负责人可回答业务，不熟悉技术形态、测试包条件或安全限制时不要现场猜测。
- 技术形态未知时，记录由哪位应用负责人在何时补充；采集条件未知时，记录确认责任人和日期即可。
- 若对方继续描述多个流程，请其按“历史问题价值＋流程稳定性”只选一条。
- 本环节不讨论采集工具、内嵌模块、调试开关和网络报文获取方式，这些留给技术专题会。

**必须得到：** 流程名称、入口、关键步骤、成功结果；技术形态或补充责任人；测试包与客户端配合确认人；安全限制确认人。

### 3. 首批范围与优先级（8:00～12:00）

**主问：**

> 首批最多选择五至八项可验证规则。请把下面三类分别归入“P0 提测前必须修复”“P1 提醒并人工确认”“后续再建”：①空白页、主流程中断、脚本/资源/接口异常；②三端一致性和视觉还原；③加载体验。

**必要追问：**

> 请明确一期不做什么。三端一致性和视觉还原若列为 P0，最具体指的是哪一个页面、哪一个区域或哪一种差异？

**必须得到：** 每类范围的分级、首批具体对象、至少一项明确非目标。

**不要展开：** 像素容差、性能阈值、模型识别能力和设备全量清单，这些由专项会确定。

### 4. 报告、豁免与视觉责任（12:00～15:00）

**主问一：**

> 如果采用报告准入，测试、发布管理、研发负责人中，谁对“允许进入测试”最终负责？请只指定一个最终责任角色，其他角色可作为协作方。

**主问二：**

> 紧急提测或工具不可用时是否允许豁免？由谁审批，是否要求记录原因、范围和有效期？

**视觉责任追问：**

> 您填写的“开发完成回检”，是否指研发先按设计基线自检，设计提供基线并仲裁争议差异？如果不是，请用一句话说明期望分工。

**必须得到：** 一个最终核验角色、豁免责任方式、视觉责任方式。

### 5. AI 边界（15:00～16:00）

**主问：**

> 您同时选择了“AI 直接判断是否可以提测”和“疑似问题必须人工确认”。是否接受一期 AI 只做推荐、补漏、摘要和脚本辅助，最终结果必须由人确认，不直接改变提测状态？

- 若接受：记录一期 AI 辅助边界。
- 若不接受：记录需要单独评审的自动判定场景、责任和风险，不承诺实现。

### 6. 三项成功标准（16:00～18:00）

**主问：**

> 第 13 题实际选择了八项。请现在只选三项作为试点继续投入的主评价指标，其余作为基础交付条件或观察项，不再全部列为最高优先级。

可快速朗读八项：提前拦截问题、提测后基础缺陷减少、人工巡检减少、结果稳定、报告支持定位、测试采用报告、维护量可接受、完成既定功能和接入。

**必须得到：** 编号 1、2、3 的三项主指标。具体数值和基线由 PoC 采样后确定，不在本会议拍脑袋设阈值。

### 7. 责任人与材料（18:00～19:00）

**主问：**

> 请确认三类责任：谁最终确认需求范围，哪个团队长期维护工具，谁裁决规则和范围争议？请同时确认核心流程、典型缺陷和当前提测/豁免流程由谁在何时提供。另请指定一名协调人，负责组织 Android、iOS、鸿蒙测试包及终端安全条件确认。

若无法当场指定完整团队，至少指定一名协调责任人，由其认领或转派 App 条件确认，并记录补充日期。

## 4. 会后书面补问，不占会议时间

1. **第 11 题数据边界**：是否接受数据只保存在部门内、不默认接入安全扫描、版本查询失败可手工补录、一期主动走查而非全量定时巡检。
2. **责任表**：需求范围、试点研发配合（含 Android、iOS、鸿蒙测试包协调）、检查规则和报告准入、长期维护、争议裁决的完整责任人。
3. **参会人**：应用/客户端、测试、设计、后端、架构、终端安全、研发协同接口等哪些角色必须参加专题会。
4. **材料与 App 采集条件**：流程页面清单、设计基线样例、当前提测与豁免流程、典型缺陷记录；另由客户端或终端安全负责人补充：
   - 测试包及客户端配合条件，是否允许测试包开启 WebView 检查或增加最小走查标识；
   - 设备和机型范围、企业设备管理、禁止截屏、调试限制、证书固定等已知约束；
   - 禁止采集或保存的页面、截图区域、账号信息和网络字段。
5. **耗时评价**：不同流程 PoC 完成后，再确认可接受额外耗时，不要求需求负责人在本次会议预估。

## 5. 会议结果判定

会议成功不要求所有细节都有答案，但必须满足以下任一结果：

- **可进入 PoC 需求冻结**：一期路径、试点流程、范围分级、关键责任和三项成功标准均已明确；测试包、客户端配合与安全限制如尚未明确，均已有确认责任人和日期；其他剩余项同样有责任人和日期。
- **转入公司系统能力评估**：需求负责人明确硬阻断是一期强制目标。
- **继续阻塞需求决策**：目标或门禁路径仍无法决定，且没有最终决策人和日期；此时不得由开发团队自行选择默认路径全面开工。
