# AI 协作文档

本目录保存供不同 AI 工具和两位开发者共同使用的项目记忆。文档内容以中文为主，文件名和任务编号使用稳定的 ASCII 形式，便于跨工具、跨平台检索。

## 阅读顺序

1. 根目录 `AGENTS.md`：不可绕过的规则与工作方式。
2. [项目上下文](project-context.md)：当前事实、建议、问卷输入和未决问题。
3. [资料登记册](source-register.md)：原始资料用途、可信边界和已知冲突。
4. [工程约束](engineering-guardrails.md)：架构、安全、数据和验证要求。
5. [路线图](roadmap.md)：当前阶段、近期任务和阶段出口。
6. [协作规范](collaboration.md)：两位开发、多种 AI 工具的并行协作方法。

按需阅读：

- `decisions/`：架构和协作决策记录（ADR）。重要分歧不能只在聊天中解决。
- `tasks/`：独立任务说明和验收记录。任务文件不是需求方决策的替代品。
- `handoffs/`：跨开发者、跨 AI 会话交接记录。

## 文档性质

- `docs/` 下原始交接、需求、调查和问卷资料是项目输入。
- 本目录多数是**派生导航与协作记录**，不得反向篡改原始事实。
- ADR 只有在有权的人类决策人确认后才能成为正式决策。
- 问卷答案是利益相关方输入，不自动成为需求基线。
- 路线图是当前工作建议，不是已批准排期。

## 更新责任

| 变化 | 必须同步的位置 |
|---|---|
| 新问卷、访谈或会议结论 | 原始回收资料、`project-context.md`、`source-register.md`、相关待办 |
| 一期目标或范围变化 | 原始决策记录、`project-context.md`、`roadmap.md`，必要时新增 ADR |
| 技术路线、跨模块接口或数据边界变化 | 新增 ADR，更新 `engineering-guardrails.md` 和受影响任务 |
| 开发任务开始或交接 | 独立任务文件、独立交接文件 |
| 协作规则变化 | 根目录 `CONTRIBUTING.md`、`AGENTS.md` 和本目录 `collaboration.md` |
| 工具变化 | 只调整对应轻量适配入口；共同规则仍在 `AGENTS.md` 和本目录 |

## 防止多 AI 记忆漂移

- 共同事实只保留一个权威位置，其他文件使用链接或简短摘要。
- 不让不同工具分别维护互不一致的长篇规则文件。
- 不用聊天历史作为唯一决策依据；重要结论必须落盘并标明决策状态。
- 不覆盖他人交接文件，不在共享“当前状态”文件中争抢编辑。
- 每次更新写明日期；废弃结论保留历史并指向替代它的 ADR 或文档。
