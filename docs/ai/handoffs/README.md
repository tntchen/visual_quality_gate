# 跨开发与跨 AI 会话交接

交接文件用于恢复上下文，不用于替代任务验收或 ADR。每次交接新建文件，不覆盖其他人的记录。

## 命名

`YYYY-MM-DD-<任务编号>-<开发或会话标识>.md`

例如：`2026-11-15-DISC-003-dev-a.md`。没有正式任务编号时，可使用清晰的短名称。

## 最小内容

复制[交接模板](handoff-template.md)，至少写清：

- 任务、分支和提交号；
- 完成内容和实际修改文件；
- 验证命令、结果及未执行项；
- 工作区和未提交修改状态；
- 未决问题、阻塞和唯一下一步；
- 相关原始资料、任务和 ADR。

## 接手规则

1. 先检查 Git 状态和实际文件，不只相信交接摘要。
2. 阅读任务对应原始依据和最近 ADR。
3. 确认未提交修改归属，不清理、不覆盖。
4. 复核关键结论后再继续；发现交接过期时新增说明。
5. 新会话产生重要进展时再建一份交接，保留历史。
