# 独立任务记录

任务记录用于让两位开发和不同 AI 工具理解同一件工作的范围与验收，不替代 Git 分支、合并请求或正式需求决策。

## 使用方式

1. 优先关联团队 Git 平台的 Issue；没有 Issue 时，在本目录创建独立任务文件。
2. 复制 [任务模板](task-template.md)，命名为 `TASK-<编号>-<短名称>.md`。
3. 开始前填写主责人、分支、范围、非目标和验收条件。
4. 工作中追加实际验证和决策，不频繁改写共享总看板。
5. 跨人或跨 AI 会话时，在 `docs/ai/handoffs/` 另建交接文件并相互链接。

## 并行规则

- 一个任务一个主责分支，避免两人同时编辑同一任务文件。
- 需要拆分时创建新任务，记录依赖和合并顺序。
- 公共接口或公共模型任务先完成接口评审，再并行实现。
- 任务状态建议为 `待开始`、`进行中`、`待评审`、`阻塞`、`已完成`。
- 只有实际验收完成后才能标记“已完成”；等待需求方结论时使用“阻塞”，不能默认继续扩大实现。

当前阶段的建议工作项统一登记在 `docs/ai/roadmap.md`，本目录暂不预建大量空任务。
