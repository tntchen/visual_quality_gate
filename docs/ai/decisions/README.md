# 架构与项目决策记录（ADR）

ADR 用于记录会影响后续开发、难以轻易逆转或需要跨两位开发保持一致的重要决策。日常文案、小实现偏好和局部修复不必建立 ADR。

## 何时新增

- 技术栈、采集路线、部署形态或存储方案变化；
- 公共数据模型、跨模块接口和统一状态变化；
- 数据边界、权限、安全和 AI 使用方式变化；
- 软门禁、硬阻断或一期系统边界发生正式决策；
- 两位开发需要长期遵循的协作规则变化。

## 状态约定

- `proposed`：建议方案，尚未获得有权决策人确认。
- `accepted`：已获人类有权决策人确认，必须记录决策人和日期。
- `rejected`：评审后未采用，保留理由。
- `superseded`：被更新 ADR 替代，必须指向新 ADR。
- `deprecated`：不再适用但未被单一 ADR 替代，说明原因。

AI 可以起草 `proposed`，不能自行把业务或技术决策标为 `accepted`。

## 编号和修改

- 文件名：`NNNN-short-title.md`，编号创建后不复用。
- 复制 [ADR 模板](adr-template.md) 新建文件。
- 已接受 ADR 的背景和结论不直接改写；变化时新增 ADR 并建立双向链接。
- ADR 只记录一个核心决策，相关内容链接到任务、原始依据和验证记录。
